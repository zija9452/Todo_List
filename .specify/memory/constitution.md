# Evolution of Todo Constitution

## Core Principles

### I. Spec-Driven Development (SDD)
Every feature and change begins with a formal specification; Specifications must precede implementation; Clear requirements and acceptance criteria are mandatory before coding begins.

### II. Agent-Generated Code (NON-NEGOTIABLE)
No manual coding allowed; All code must be generated by AI agents; Maintain audit trail of all changes through automated generation; Human role is to guide, validate, and approve.

### III. Clean Python Architecture
Python 3.13+ required; Type hints mandatory; Modular, well-structured codebase; Follow PEP 8 and modern Python conventions; Clean separation of concerns.

### IV. Test-First Approach (NON-NEGOTIABLE)
TDD mandatory: Tests written → Requirements validated → Tests fail → Then implement; Unit tests required for all features; Test coverage must pass before merge; Red-Green-Refactor cycle strictly enforced.

### V. Minimal Storage Approach
In-memory storage only; No external databases or services; Keep implementation simple and lightweight; State persistence not required beyond application lifetime.

### VI. CLI-First Interface
Command-line interface mandatory; Text-based input/output protocol; Support both human-readable and structured formats; Console interaction for all core functionality.

## Additional Constraints

Technology stack: UV package manager, Python 3.13+, Claude Code, Spec-Kit Plus; Must run on Linux/WSL2 environment; No external services or network dependencies; In-memory only storage (no persistent databases); Clean project structure with src/, specs_history/, tests/ directories.

## Development Workflow

All development follows Spec → Plan → Tasks → Implement sequence; Feature specifications in specs_history/ directory; Unit tests must pass before merging; Documentation updates required with code changes; PRs must include spec alignment verification; Automated testing gate required.

## Governance

This constitution governs all development activities; Amendments must be documented and approved; All contributors must acknowledge compliance; Code reviews verify adherence to principles; Deviations require explicit justification and approval.
