# Evolution of Todo Constitution

## Core Principles

### I. Spec-Driven Development (SDD)
Every feature and change begins with a formal specification; Specifications must precede implementation; Clear requirements and acceptance criteria are mandatory before coding begins.

### II. Agent-Generated Code (NON-NEGOTIABLE)
No manual coding allowed; All code must be generated by AI agents; Maintain audit trail of all changes through automated generation; Human role is to guide, validate, and approve.

### III. Full-Stack Web Architecture
Transform Phase I CLI into a multi-user persistent Full-Stack Todo app via Spec-Driven Claude Code; Modern tech stack: Next.js 16+ (TypeScript), FastAPI, SQLModel; Multi-user persistent application; REST API backend with secure endpoints; Responsive frontend interface; Proper separation of concerns between frontend and backend.

### IV. Test-First Approach (NON-NEGOTIABLE)
TDD mandatory: Tests written → Requirements validated → Tests fail → Then implement; Unit tests required for all features; Test coverage must pass before merge; Red-Green-Refactor cycle strictly enforced; Both backend unit/integration and frontend smoke tests required; CI runs pytest + frontend checks.

### V. Persistent Data Storage
Neon Postgres database required; Proper data modeling with relationships; ACID transactions and data integrity; Schema evolution strategies; Backup and recovery considerations.

### VI. Secure Authentication System
Better Auth for JWT-based authentication; Better Auth issues JWT (BETTER_AUTH_SECRET); backend verifies token, enforces ownership, 401 on failure; Proper token validation and refresh mechanisms; User session management; Access control and authorization enforcement; Secure password handling and storage.

### VII. API-First Design
RESTful API design principles; API (secured): GET/POST/GET/PUT/DELETE /api/{user_id}/tasks and PATCH /complete — all require Bearer JWT; Proper endpoint structure: GET/POST/PUT/DELETE /api/{user_id}/tasks and PATCH /complete; All endpoints require Bearer JWT; Proper error handling and status codes; Rate limiting and throttling considerations.

### VIII. Data Model Governance
Standardized data schema: tasks(id, user_id, title, description, completed, priority, due_date, created_at, updated_at); Foreign key relationships; Data validation and sanitization; Ownership enforcement at database and API layers; Audit trails for data changes.

### IX. Development and Repository Standards
Monorepo with /specs, /frontend, /backend, .spec-kit/config.yaml, CLAUDE.md, .env.example; Spec-first approach with plan artifacts per spec; Code generated by Claude Code with atomic commits referencing spec id; Backend unit + integration tests and frontend smoke tests; CI runs pytest + frontend checks.

## Additional Constraints

Technology stack: Next.js 16+ (TS), FastAPI + SQLModel, Neon Postgres, Better Auth, Claude Code, Spec-Kit Plus; Environment configuration via .env files; Proper CORS and security headers; JWT secret management (BETTER_AUTH_SECRET); Cross-platform compatibility for development; Enforce ownership checking between user_id in JWT and user_id in API path; Scope: REST API + Next.js frontend + Better Auth (JWT) + Neon Postgres + FastAPI/SQLModel.

## Development Workflow

All development follows Spec → Plan → Tasks → Implement sequence; Feature specifications in specs/ directory; API endpoints must enforce JWT authentication and user ownership; Documentation updates required with code changes; PRs must include spec alignment verification; Automated testing gate required for both frontend and backend; Atomic commits with spec id references; Transform Phase I CLI into a multi-user persistent Full-Stack Todo app via Spec-Driven Claude Code.

## Governance

This constitution governs all development activities; Amendments must be documented and approved; All contributors must acknowledge compliance; Code reviews verify adherence to principles; Deviations require explicit justification and approval; API security and data privacy compliance mandatory; Purpose: Transform Phase I CLI into a multi-user persistent Full-Stack Todo app via Spec-Driven Claude Code.
